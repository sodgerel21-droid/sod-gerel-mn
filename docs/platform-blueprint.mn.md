# E-Property платформын нэгдсэн санал

Огноо: 2026-09-29. Төлөв: бүтээгдэхүүн ба архитектурын санал.

## 1. Бүтээгдэхүүний зорилго

e-property.mn нь барилга эхлээгүй төлөвлөлтийн шатнаас ашиглалтад орж, өмчлөх эрх бүртгэгдэх хүртэл төсөл, нэгж байр, гэрээ, төлбөр, баталгаажуулалтын түүхийг холбоно. Орон сууц, оффис, үйлчилгээний талбай, зогсоолыг хамарна.

Үндсэн амлалт: **Нэгж бүр тодорхой таних дугаартай, мэдээлэл бүр эх сурвалжтай, өөрчлөлт бүр түүхтэй байна.**

Эрхийн албан бүртгэлийн эх сурвалж нь УБЕГ; зөвшөөрөл, зураг, ашиглалтад орсон мэдээллийн эх сурвалж нь тухайн мэдээллийг хариуцсан эрх бүхий байгууллага; газрын мэдээллийн эх сурвалж нь холбогдох газрын систем байна. Платформ эдгээрийг холбоод захиалга, гэрээ, хүсэлтийн явцыг удирдана.

Домэйн нь улсын байгууллагын статус, интеграцийн зөвшөөрөл, эрхийн баталгаа өөрөө үүсгэхгүй. Нийтийн хуудсанд оператор байгууллага болон төрийн системтэй холбоотой бодит хамрах хүрээг тодорхой харуулна.

## 2. Хавсаргасан саналаас авсан ба сайжруулсан шийдвэр

| Санаа | Хэрэгжүүлэх шийдвэр |
|---|---|
| Project → Building → Unit | Үндсэн өгөгдлийн загварт авна; орц, давхар нэмэлт бүтэц байна |
| Permanent Unit ID | Өөрчлөгдөхгүй дотоод ID; тоот, хаяг, улсын бүртгэлийн дугаарыг тусдаа хадгална |
| Зураг төслийн хувилбар | Талбай, зориулалт, төлөвлөлт, нэгтгэл/хуваалтын өмнөх ба дараах түүх хадгална |
| Давхар борлуулалтын хяналт | Платформ дотор зөрчилтэй идэвхтэй захиалга/гэрээг зэрэг батлахгүй |
| Төрийн мэдээллээр шалгах | Талбар бүрийн эх сурвалж, шалгасан огноо, баталгаажуулалтын аргыг харуулна |
| Барих ба борлуулах бэлэн байдлыг салгах | Барилгын зөвшөөрөл болон платформын борлуулалтын шалгуурыг тусдаа хөтөлнө; Монголд тусдаа төрийн борлуулах зөвшөөрөл бий гэж урьдчилан үзэхгүй |
| Escrow / төслийн тусгай данс | Банкны гэрээ, дансны бодит нөхцөлтэй холбосон дараагийн үе шат |
| Барилга дуусгах баталгаа | Банк/даатгагч/батлан даагчийн бүтээгдэхүүн бий болсон үед нэмэх |
| Ил тод төслийн мэдээлэл | Төслийн паспорт, нийтэд нээлттэй баримт, үнэ, нэгжийн хүртээмж, гүйцэтгэл |
| Нэг өмчлөгчийн холбоос | Хамтран худалдан авагч, хувь эзэмшил, төлөөлөгч, эрх шилжилтийг дэмжинэ |

Хавсралтад дурдсан УБЕГ-ын шинэ E-PROPERTY систем нэвтэрсэн огноо, Э-07 үйлчилгээ болон тодорхой API боломжийг энэ баримтад баталгаажсан факт гэж ашиглаагүй. Нэвтрэх ба тоон гарын үсгийн үйлчилгээ үзүүлэгчийг мөн урьдчилан сонгоогүй.

## 3. Дэлхийн жишгээс авах механизм

- **Дубай / Oqood:** төсөл, нэгж, урьдчилсан хэлцлийн бүртгэл, төслийн дансны уялдаа. [DLD — төслийн бүртгэл](https://backoffice.dubailand.gov.ae/en/eservices/register-project/), [урьдчилсан бүртгэлийн тайлбар](https://backoffice.dubailand.gov.ae/en/frequently-asked-questions/).
- **Сингапур / URA:** хөгжүүлэгчийн хяналт, стандарт гэрээ, төсөл тус бүрийн данс. Монголд гэрээ ба төлбөрийн шалгуурыг тодорхой болгоход ашиглана. [URA — хөгжүүлэгч](https://www.ura.gov.sg/guidelines/developers/housing-developers/), [худалдан авагч](https://www.ura.gov.sg/guidelines/property-and-business-owners/property/buying-property/).
- **БНСУ / HUG:** тодорхой нөхцөлд барилга дуусгах эсвэл урьдчилгаа, явцын төлбөрийг буцаах баталгааны бүтээгдэхүүн. Монголд түнш байгууллагын баталгааны гэрээгүйгээр ийм хамгаалалттай гэж тэмдэглэхгүй. [HUG бүтээгдэхүүн](https://www.khug.or.kr/hug/web/en/02/en02000001.jsp).
- **Австрали / NSW:** худалдан авагчид чухал өөрчлөлтийг мэдээлэх хамгаалалт. Зураг, талбай, хугацааны өөрчлөлтөд мэдэгдэл, хүлээн авсан баримт, шаардлагатай зөвшөөрөл, маргаан/цуцлалтын урсгал нэмнэ. Монголын нөхцөлийг гэрээ, холбогдох хуулиар тогтооно. [NSW албан тайлбар](https://www.nsw.gov.au/housing-and-construction/buying-and-selling-property/buying-property-nsw/buying-property-off-plan).
- **Хонконг / SRPA:** төслийн танилцуулга, үнийн жагсаалт, борлуулалтын мэдээллийн ил тод байдал. Нийтийн мэдээллийг хувийн гэрээ, худалдан авагчийн мэдээллээс салгана. [SRPA зааврууд](https://www.srpa.gov.hk/en/guidelines.html).

Гадаадын зохицуулалтыг Монголд үйлчилж буй хууль гэж үзэхгүй. Дээрх нь бүтээгдэхүүний механизм сонгох үндэслэл юм.

## 4. Гол өгөгдлийн загвар

```text
Developer / Organization
  Project ←→ LandParcel (нэг төсөл олон газартай байж болно)
    Permit / DesignVersion / Evidence
    Building
      Entrance / Floor
      Unit
        UnitVersion / SplitMergeLineage
        Reservation
        Contract → Parties / Shares / Signatures
        PaymentSchedule / BankTransaction / Refund
        RegistryApplication / OfficialRegistryReference
        EncumbranceReference / Handover
    ProgressReport / Inspection
    ProjectBankAccount / GuaranteePolicy
```

Дотоод ID нь байршлаас үл хамаарах UUID зэрэг тогтвортой утга байна. `A-1205` нь хэрэглэгчид харагдах дугаар; хаяг, тоот өөрчлөгдсөнөөр үндсэн ID солигдохгүй. Нэгж нийлсэн/хуваагдсан үед шинэ ID үүсгэж, өмнөх объектуудыг түүхэн төлөвт оруулан холбоно. Идэвхтэй гэрээтэй нэгжийг өөрчлөхөд эрх бүхий хяналт шаардана.

Улсын бүртгэлийн холбоосыг бүртгэлийн хамрах хүрээтэй хадгална: газар, бүхэл барилга, хувь эсвэл нэгж. Барилгын бүртгэлийг бүх нэгжид тусдаа эрх олгосон мэт дамжуулж болохгүй.

## 5. Төлөвүүдийг тусдаа удирдах

| Хэмжээс | Жишиг төлөвүүд |
|---|---|
| Барилга | Төлөвлөсөн, зөвшөөрөгдсөн, баригдаж буй, дууссан, ашиглалтад орсон, түр зогссон |
| Борлуулалт | Нээлтгүй, боломжтой, түр хадгалсан, захиалсан, гэрээлсэн, шилжүүлсэн, цуцалсан |
| Эрхийн хүсэлт | Илгээгээгүй, материал бүрдүүлж буй, илгээсэн, хянаж буй, буцаасан, татгалзсан, албан бүртгэл баталгаажсан |
| Төлбөр | Төлөгдөөгүй, хэсэгчлэн төлсөн, төлсөн, хугацаа хэтэрсэн, буцаалт хүлээгдэж буй, буцаасан |
| Мэдээллийн баталгаа | Мэдүүлсэн, баримтаар шалгасан, эх системээр шалгасан, хуучирсан, зөрчилтэй, шалгах боломжгүй |

Барилгын явц 40% байх үед борлуулалт гэрээлсэн, төлбөр хэсэгчлэн төлсөн, бүртгэлийн хүсэлт хянагдаж буй зэрэг төлөв зэрэгцэн оршино. Дээрх жишиг төлөвүүдийн шилжилт, эрх, нотлох баримтыг хөгжүүлэлтийн үед нарийвчилна.

Борлуулалтын тооллогод `эрх бүртгэгдсэн` нэгжийг `гэрээлсэн` тоон дээр дахин нэмж нийт гаргахгүй. Өөр хэмжээсийн үзүүлэлтийг тусдаа тайлагнана.

## 6. Иргэний урсгал

1. Төслийн паспорт, газар/зөвшөөрлийн эх сурвалж, шалгасан хугацааг үзэх.
2. Нэгжийн зураг, талбайн тодорхойлолт, үнэ, төлбөрийн нөхцөл, өөрчлөлтийн түүх үзэх.
3. Танилт хийлгэж, хугацаатай түр хадгалалт үүсгэх; хугацааг төслийн бодлогоор тохируулах.
4. Захиалгын нөхцөл, мөнгө буцаах дүрэмтэй танилцан зөвшөөрөх.
5. Шаардлагатай гэрээг гарын үсгээр баталгаажуулж, гэрээнд заасан төлбөрийг хийх.
6. Банкны баталгаатай төлбөрийг гэрээтэй тулгах; баримтын зураг дангаараа банкны баталгаа болохгүй.
7. Шалгуур хангасан үед урьдчилсан тэмдэглэлийн хүсэлтийг бүрдүүлж дамжуулах.
8. Албан хариу, гүйцэтгэл, өөрчлөлтийн мэдэгдэл, хүлээлгэн өгөх явцыг хувийн хэсгээс хянах.

Төлбөр орсон ч түр хадгалалтын хугацаа дууссан зэрэг зөрчилд шууд шинэ гэрээ батлахгүй; шалгах/буцаах урсгалд оруулна. Цуцлалт нь холбогдох эрх, төлбөрийн нөхцөлийг шийдвэрлэхээс өмнө байрыг автоматаар дахин борлуулахгүй.

## 7. Интеграц ба эрх зүйн нөхцөл

Монголын Эд хөрөнгийн эрхийн улсын бүртгэлийн тухай хуулийн 31.2-т барьж дуусаагүй барилгын эрх бүртгэгдсэн үед захиалагч урьдчилсан тэмдэглэл хийлгэх боломжийг заасан. Бүртгэл хөтлөх журмын 22.2-т захиалгын гэрээ, оруулсан хөрөнгийн нотолгоо хавсаргана. Эдгээр нь бүх төлөвлөсөн нэгжид автоматаар эрх үүсгэх үндэслэл биш. [Хууль](https://legalinfo.mn/mn/detail/13589), [журам](https://legalinfo.mn/mn/detail?lawId=209069).

| Систем / тал | Төлөвлөсөн хэрэгцээ | Баталгаажуулах зүйл |
|---|---|---|
| УБЕГ | Бүртгэлийн лавлагаа, зөвшөөрөгдсөн эрх/хязгаарлалт, хүсэлт, шийдвэр | Сервис бүрийн эрх, хамрах хүрээ, өгөгдөл, бичих боломж |
| Барилгын салбарын байгууллагууд | Төсөл, зөвшөөрөл, зураг, ашиглалтад орсон мэдээлэл | Өгөгдөл эзэмшигч, үйлчилгээний бодит хүртээмж |
| Газрын систем | Нэгж талбар, газрын эрх, хил зааг | Холбох ID, мэдээлэл ашиглах нөхцөл |
| ДАН / танилтын үйлчилгээ | Нэвтрэлт, этгээдийг таних | Холболтын гэрээ, төлөөлөх эрхийн шалгалт |
| Тоон гарын үсэг | Гэрээ, шийдвэр баталгаажуулах | Үйлчилгээ үзүүлэгч, баримтын баталгаажуулалт |
| Банк | Төлбөр, буцаалт, төслийн данс | API, дансны төрөл, мөнгө чөлөөлөх эрх |

Төрийн холболтыг `лавлагаа → хүсэлт дамжуулах → албан шийдвэр тулгах` гэсэн түвшнээр хэрэгжүүлнэ. Лавлагаа авах эрх нь бүртгэл өөрчлөх эрхийг орлохгүй. API байхгүй үед баримт бүрдүүлэлт, эрх бүхий ажилтны хяналт, албан хариу хавсаргах урсгал ашиглаж болно.

Яамны салбарын системүүд: [албан сайт](https://mcud.gov.mn/home?locale=mn). ХУР/ДАН холболт: [албан гарын авлага](https://guide.datacenter.gov.mn/books/gereegovmn-sistemiig-asiglax-garyn-avlaga/page/xolboltyn-caxim-garyn-avlaga).

## 8. e-property.mn дээрх бүтээгдэхүүний бүтэц

Брэндийн дэлгэрэнгүй чиглэл: [Брэнд ба нүүр хуудас](brand-and-landing.mn.md).

Зорилтот домэйн бүтэц:

| Хаяг | Зориулалт |
|---|---|
| `e-property.mn` | Нийтийн сайт, төслүүд, иргэний хувийн хэсэг |
| `developer.e-property.mn` | Барилгын төсөл хэрэгжүүлэгчийн портал |
| `admin.e-property.mn` | Операторын удирдлага; эрх бүхий байгууллагын оролцоо тохиролцсон үед тусгай эрхээр |
| `api.e-property.mn` | Порталууд болон зөвшөөрөгдсөн түншүүдийн API |

Доорх нь хэрэглэгчийн хэсгүүдийн логик маршрут. `/developer`, `/admin` хэсгийг дээрх тусдаа хостод байршуулна:

- `/projects` — төслүүд, газрын зураг, хайлт.
- `/projects/:id` — төслийн паспорт, нэгжүүд, нийтэд нээлттэй баримт.
- `/units/:id` — зураг, үнэ, хүртээмж, мэдээллийн баталгаа.
- `/verify/:reference` — зөвхөн нийтэд үзүүлэхээр зөвшөөрсөн баримтын QR шалгалт.
- `/account` — иргэний захиалга, гэрээ, төлбөр, хүсэлт.
- `/developer` — байгууллагын төсөл, нэгж, гэрээ, тайлан.
- `/partners` — банк, бусад түншийн зөвшөөрөгдсөн мэдээлэл.
- `/admin` — операторын хяналт, мэдээллийн зөрчил, аудит.

Эдгээр нь санал болгож буй маршрут; одоогоор нийтлэгдээгүй. URL нуух нь хамгаалалт болохгүй; сервер талд байгууллага болон объектын түвшинд эрх шалгана. QR кодоор худалдан авагчийн хувийн мэдээлэл задруулахгүй.

## 9. Архитектур ба ажиллагааны шаардлага

Эхний хувилбар: модулиар тусгаарласан backend, PostgreSQL/PostGIS, хувилбартай баримтын сан, асинхрон ажлын дараалал, гадаад систем тус бүрийн адаптер. Property Graph гэдэг нь мэдээллийн холбоосын загвар; тусгай graph database эхний үед шаардахгүй.

- Нэгжид зэрэг ирсэн захиалгыг өгөгдлийн сангийн transaction/locking ба давхардлын хязгаарлалтаар хамгаалах.
- Төлбөр, хүсэлт давтан ирэхэд дахин үйлдэл үүсгэхгүй idempotency хэрэгжүүлэх.
- Гадаад хариу хоцрох, тасалдах үед pending төлөв хадгалж, дахин тулгах.
- Байгууллага хооронд өгөгдөл тусгаарлах; чухал өөрчлөлтөд хоёр шатны хяналт, админд MFA хэрэглэх.
- Эх баримт, гарын үсэг, хувилбар, өөрчлөлт хийсэн этгээдийг аудиттай хадгалах; засварыг түүхэн бичлэг устгаж хийхгүй.
- Нөөцлөлт, сэргээх туршилт, мэдэгдэл, мониторинг, өгөгдлийн хадгалах хугацааг ажиллагааны бодлогоор тогтоох.
- Нийтэд хувийн гэрээ, регистр, банкны данс гаргахгүй; мэдээлэл ашиглах үндэслэл ба зөвшөөрлийг хөтлөх.

Платформын давхардлын хамгаалалт нь хамрагдсан борлуулалтын сувгуудад үйлчилнэ. Гадуурх бүх хэлцлийг хаах баталгаа гэж сурталчлахгүй. Гүйцэтгэлийн хувь, газар/зөвшөөрөл шалгагдсан тэмдэг нь хөрөнгө оруулалт эрсдэлгүй гэсэн баталгаа болохгүй.

## 10. Үе шат ба хүлээн авах шалгуур

**I — Бэлтгэл:** байгууллагуудын мэдээллийн зураглал, операторын үүрэг, нэгжийн ID стандарт, гэрээ/цуцлалт/өөрчлөлтийн дүрэм, туршилтын төсөл. Бодит API баримт, тест орчин, хандалтын нөхцөлийг баталгаажуулна.

**II — MVP:** төслийн паспорт, нэгжүүд, баримтын баталгаажуулалт, хувилбарын түүх, хугацаатай захиалга, гэрээ, төлбөрийн нотолгоо, бүртгэлийн хүсэлтийн материал, иргэн/хөгжүүлэгч/операторын хэсэг.

**III — Интеграцтай туршилт:** зөвшөөрөгдсөн төрийн лавлагаа, хүсэлт/шийдвэр, банкны төлбөр тулгалт. 2–3 төсөл, нэг банктай эхлэх саналтай.

**IV — Өргөтгөл:** банкны нөхцөлт данс, баталгаажсан гүйцэтгэлд тулгуурласан санхүүжилт, гэрээтэй баталгааны бүтээгдэхүүн, ипотек, түншийн API.

Туршилтын үндсэн шалгуур:

1. Нэг нэгжид зэрэг захиалга ирэхэд зөвхөн нэг хүчинтэй хадгалалт үүсэх.
2. Банкны давтан мэдэгдэл төлбөрийг хоёр удаа тооцохгүй байх.
3. Талбай/зураг өөрчлөгдөхөд өмнөх хувилбар, нөлөөлсөн гэрээ, мэдэгдэл харагдах.
4. Албан хариугүй хүсэлт “эрх бүртгэгдсэн” төлөвт орохгүй байх.
5. Холболт тасрахад мэдээллийг шинэ баталгаа мэт харуулахгүй байх.
6. Өөр байгууллагын гэрээ/хувийн мэдээлэлд нэвтрэх боломжгүй байх.
7. Цуцлалт, буцаалт, нэгжийн дахин нээлтийг холбоотой журмаар шийдэх.

Дараагийн хэрэгжүүлэлтийн суурь нь энэ саналд тулгуурласан дэлгэцийн загвар, өгөгдлийн схем, API гэрээ байна. DNS болон хостингийн бодит тохиргоог сонгосон орчин, домэйны хандалт тодорхой болсны дараа хийнэ.
