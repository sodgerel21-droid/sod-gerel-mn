# E-Property — сайжруулалтын санал ба 3D харагдацын стратеги

Огноо: 2026-09-30, шинэчилсэн 2026-10-03. Төлөв: санал. Холбоотой баримт: [platform-blueprint.mn.md](platform-blueprint.mn.md).

## 1. Одоогийн байдлын дүгнэлт

- **Код:** Nexus `backend/v1.20.2` дээрх дистрибуц. Нэвтрэлт, байгууллага, эрхийн суурь бий. Төсөл, нэгж, захиалга, гэрээ, төлбөрийн модуль хараахан эхлээгүй.
- **Бүтээгдэхүүний баримт:** Blueprint бүтэц, хууль эрх зүйн болгоомжлол, олон хэмжээст төлөв, idempotency, давхар борлуулалтын хамгаалалт, гадаадын жишиг (Дубай, Сингапур, БНСУ, NSW, Хонконг) зөв сонгогдсон.
- **Гол цоорхой:** Нэгжийг зөвхөн өгөгдлийн мөр гэж загварчилсан. Орон зайн (2D/3D) тодорхойлолт, зураг төслийн файлтай холбох арга, талбайн зөрүүг шийдэх дүрэм тодорхойгүй.

## 3. 3D харагдацын түвшин

Бүх зургийг 3D болгох шаардлагагүй. Нийтэд харуулах болон эрхтэй хэрэглэгчид харуулахыг тусад нь зохион байгуулна.

| Түвшин | Агуулга | Web технологи | Хандалт |
|---|---|---|---|
| L1 Газрын зураг | Барилгын массинг, байршил, газрын нэгж талбар | MapLibre (fill-extrusion) эсвэл Cesium + 3D Tiles | Нийтэд |
| L2 Барилга | Орц, давхар, нэгжийг борлуулалтын төлөвөөр өнгөлөх | three.js + glTF/GLB (Draco/Meshopt, KTX2) | Нийтэд |
| L3 Нэгж | Байрны төлөвлөлт, өрөө, талбай, 3D дотор тал | IFC → That Open Fragments эсвэл glTF | Нийтэд |
| L4 Ажлын зураг | Архитектур, конструкц, инженерийн хуудсууд, зангилаа | 2D DWG → PDF/SVG, 3D-ээс hotspot-оор холбох | Зөвхөн эрхтэй хэрэглэгч |

- Нэгж дээр дарахад нэгжийн паспорт нээгдэнэ. Төлөвийн өнгийг API-гаас авах ба өнгөнөөс гадна тайлбар, дүрсээр давхар илэрхийлнэ.
- Конструкц, инженерийн дэлгэрэнгүй зураг аюулгүй байдал болон оюуны өмчтэй холбоотой. Тиймээс нийтэд L1–L3-ыг л харуулна.

### 3.1 Хоёр урсгал: «Үнэн зөв» ба «Гоё харагдац»

Хоёр урсгал **нэг баталгаажсан геометрээс** гарна. Ялгаа нь зөвхөн харагдац, зориулалт, хариуцлагад байна.

| | Мэргэжлийн («Үнэн зөв») | Маркетингийн («Гоё харагдац») |
|---|---|---|
| Зориулалт | Гэрээ, талбай, баталгаажуулалт, инженер, банк, хяналтын байгууллага | Төслийн хуудас, нэгжийн карт, сошиал, зар сурталчилгаа |
| Эх сурвалж | IFC эсвэл DWG → ezdxf / IfcOpenShell, оператор шалгасан | Мэргэжлийн урсгалын геометр (хана, цонх, хаалгыг өөрчлөхгүй) |
| Харагдац | 2D төлөвлөлт, хэмжээсийн шугам, тэнхлэг, талбайн хүснэгт; 3D-д энгийн саарал материал, хэсэглэл, давхраар харах | Изометрик dollhouse, бодит материал, гэрэлтүүлэг, сүүдэр, автомат тавилга, стилийн сонголт |
| Технологи | That Open / web-ifc, three.js, SVG/PDF | three.js (интерактив), Blender/headless (статик PNG), сонголтоор AI enhance |
| Үйлдэл | Хэмжих, хэсэглэх, давхар солих, хувилбар харьцуулах, шинж чанар харах | Эргүүлэх, өдөр/шөнө, стиль солих, татах, хуваалцах |
| Баталгаа / шошго | `DesignVersion`, файлын hash, шалгасан огноог харуулна | «Дүрслэл — тавилга, материал жишээ» гэсэн тэмдэглэгээ |
| Хориг | AI, тавилга, гоёлын зорилгоор хэмжээ өөрчлөхийг хориглоно | Зураг дээр талбай, хэмжээ бичихгүй |
| Хандалт | Нэгжийн төлөвлөлт нийтэд, ажлын зураг (L4) эрхтэй хэрэглэгчид | Нийтэд |

Хоёрыг холбох дүрэм:

1. **Нэг геометр:** маркетингийн render геометрээ мэргэжлийн урсгалаас авна. Эсрэг чиглэлд хэзээ ч болохгүй.
2. **Тоо нэг эх сурвалжтай:** талбай, өрөөний тоо, хэмжээг зөвхөн мэргэжлийн өгөгдлөөс харуулна.
3. **Хувилбар дагана:** `DesignVersion` солигдоход маркетингийн зургийг хуучирсан гэж тэмдэглээд автоматаар дахин render хийнэ.
4. **Нэг товчоор шилжинэ:** нэгжийн хуудсанд «Дүрслэл | Техникийн зураг» хоёр таб байна.
5. **AI шалгалт:** AI enhance хийсэн зургийн хана, цонхны байрлалыг эх render-тэй автоматаар харьцуулна. Зөрүү босгоос хэтэрвэл нийтлэхгүй.

Дараалал: эхлээд мэргэжлийн урсгал (DWG → геометр → 2D болон энгийн 3D), дараа нь three.js dollhouse болон статик PNG, хамгийн сүүлд AI enhance болон стилийн сонголт.

Гадны хэрэгслүүд: [Archilogic](https://www.archilogic.com/developers) (Floor Plan Engine SDK, Space API), [react-planner](https://github.com/cvdlab/react-planner), [blueprint3d-modern](https://github.com/charmlinn/blueprint3d-modern), [FloorplanToBlender3d](https://github.com/grebtsew/FloorplanToBlender3d), [PlanTo3D](https://github.com/priyanshsoni96-blip/PlanTo3D). Sweet Home 3D (GPL) болон CubiCasa5K өгөгдлийн сан (арилжааны бус лиценз) зэргийн лицензийг ашиглахаас өмнө шалгана.

## 4. Зургаас 3D web asset гаргах урсгал

Урсгалыг эх файлын чанараар ялгана.

**A. IFC (Revit/ArchiCAD-аас) — давуу зам, бараг автомат**

1. IFC-ийг хүлээн авч, файлын hash-ийг `DesignVersion`-д бүртгэнэ.
2. `web-ifc` / That Open ашиглан Fragments эсвэл glTF болгоно. Том загварт 3D Tiles үүсгэнэ.
3. `IfcBuildingStorey`-г давхар, `IfcSpace`-ийг нэгж болгон задлаад `model_guid ↔ unit_id` холбоос үүсгэнэ.

**B. Зөвхөн 2D DWG — Монголд түгээмэл, хагас автомат**

1. ODA File Converter-ээр DWG-г DXF болгоно.
2. `ezdxf`-ээр хана, хаалга, цонх, өрөө/нэгжийн хилийн давхаргыг уншина.
3. Давхрын өндрөөр extrusion хийж, `IfcOpenShell`-ээр IFC болон glTF үүсгэнэ.
4. Оператор шалгана: нэгжийн хил, талбай, дугаарлалт.
5. Хөгжүүлэгчдэд CAD давхаргын стандарт (layer template) өгч, шалгах ажлыг багасгана.

**C. PDF/скан зураг — зөвхөн дүрслэл**

AI-аар 3D болгож болох ч нарийвчлал нь талбай, гэрээний мэдээлэлд хүрэлцэхгүй. Үр дүнг "Жишээ дүрслэл" гэж тэмдэглэнэ. Эрх зүйн мэдээллийн эх сурвалж болгохгүй.

Бодлого: IFC өгсөн төслийг хурдан, автоматаар нийтэлнэ. Энэ нь салбарт BIM-ийг нэвтрүүлэх хөшүүрэг болно.

## 5. AutoCAD-ыг агентаар удирдах эсэх

**Санал: AutoCAD-ын GUI-г агентаар удирдахгүй.**

- Удаан, амархан эвдэрнэ, масштаблахгүй. Desktop лицензийг сервер автоматжуулалтад ашиглахад хязгаартай.
- 2D DWG-д семантик байхгүй. Шугам хана уу, нэгжийн хил үү гэдгийг AutoCAD өөрөө ч тодорхойлохгүй.
- AutoCAD-ын хөдөлгүүр заавал хэрэгтэй бол албан ёсны зам нь Autodesk Platform Services — Design Automation (үүлэн дээрх AutoCAD). Бэлэн хөрвүүлэлт, viewer хэрэгтэй бол Model Derivative (DWG/RVT/IFC → SVF2).
- Агентын үүрэг: pipeline-ыг зохион байгуулах, давхаргын нэршил таних, зөрүүг илрүүлэх, операторт шалгах жагсаалт бэлтгэх.

| Сонголт | Давуу тал | Сул тал |
|---|---|---|
| Нээлттэй эх (web-ifc, IfcOpenShell, ezdxf, three.js) | Лицензийн төлбөргүй, өгөгдөл өөрийн серверт үлдэнэ | Хөгжүүлэлт, дэмжлэгийг өөрсдөө хариуцна |
| Autodesk APS | DWG/RVT-г шууд дэмжинэ, бэлэн viewer | Хэрэглээгээр төлбөртэй, гадаад үүлэнд тулгуурлана |
| Cesium ion | Том загварын 3D Tiles, газрын зурагтай нэгтгэх | Арилжааны лиценз |

Санал болгох суурь: нээлттэй эх. Хөгжүүлэгчдийн файлын төрлүүдээс шалтгаалан APS-ийг нөөц хөрвүүлэгч болгоно.

## 6. Өгөгдлийн схемийн нэмэлт

```text
DesignVersion   (id, project_id, source_type[IFC|DWG|PDF], file_hash, uploaded_by, status)
ModelAsset      (id, design_version_id, level[L1..L4], format[glTF|Fragments|3DTiles|PDF|SVG], uri, visibility)
UnitGeometry    (unit_id, design_version_id, floor_polygon, height, model_guid, area_measured, area_method)
DrawingSheet    (id, design_version_id, discipline, sheet_no, uri, visibility)
SheetHotspot    (sheet_id, model_guid | unit_id)
```

- `DesignVersion` солигдоход `UnitGeometry`-г харьцуулна. Талбай хүлцлээс хэтэрвэл нөлөөлөх гэрээ болон худалдан авагчид мэдэгдэл үүсгэнэ (§2-ын 3).
- Visibility-ийг сервер талд байгууллага болон объектын түвшинд шалгана. URL нуух нь хамгаалалт биш.

## 7. Хэрэгжүүлэх дараалал

1. **Прототип (2–3 долоо хоног):** нэг бодит төслийн DWG → B урсгал → L2/L3 viewer, нэгжийг төлөвөөр өнгөлөх.
   Жишээ зургаар хийсэн эхний хувилбар: [tools/cad](../tools/cad/README.mn.md) — давхаргын стандарт, DXF → GLB, талбайн зөрүү, viewer. Бодит DWG-ээр шалгах нь үлдсэн.
2. **MVP-д нэгтгэх:** `DesignVersion`, `UnitGeometry`, нэгжийн паспорт, талбайн зөрүүний мэдэгдэл.
3. **IFC урсгал:** A урсгал, хөгжүүлэгчийн CAD/BIM стандарт гаргах.
4. **Газрын зураг:** L1 массинг, газрын нэгж талбартай холбох.
5. **Өргөтгөл:** явцын 4D (зураг, дрон), L4 эрхтэй хандалт, escrow-той холбох.
