# Орон сууцны төлөвлөлт: 2D · 3D · интерьер

Огноо: 2026-10-05. Төлөв: ажиллаж буй эхний босоо зүсэлт (vertical slice). Холбоотой баримт: [improvements-and-3d.mn.md](improvements-and-3d.mn.md) §3.1, [tools/cad/README.mn.md](../tools/cad/README.mn.md).

## 1. Нэг геометр

Нэгжийн 2D зураг, 3D бүрхүүл, өрөө сонголт, тавилгын байршуулалт, талбайн тооцоо, хадгалсан интерьерийн тохиргоо бүгд **нэг төлөвлөлтийн файлаас** (schema `e-property.apartment-plan` v1) гарна.

| Хэсэг | Файл |
|---|---|
| Schema, шалгалт, талбай, нүхний байрлал | `landing/units/lib/plan-geometry.js` |
| Хананы хэсгүүд (2D ба 3D хоёулаа үүнийг ашиглана) | `landing/units/lib/shell.js` |
| 2D техникийн зураг (SVG) | `landing/units/lib/plan2d.js` |
| 3D viewer (three.js 0.170) | `landing/units/lib/viewer3d.js` |
| Нэгжид төлөвлөлт сонгох | `landing/units/lib/plan-source.js` |
| Таамагласан хуваалт (бүтэцтэй төлөвлөлтгүй нэгжид) | `landing/units/lib/legacy-layout.js` |
| Жишээ бүтэцтэй төлөвлөлт | `landing/3d/data/tuul-river/plans/type-01.plan.json`, `type-01.dxf` |

### Schema-ийн гол талбарууд

- `units: "m"`. Координат нь барилгын plan.dxf-ийн хүрээ (x = DXF X, y = DXF Y, цагийн зүүний эсрэг эерэг). Координатыг тооцоонд хэзээ ч тоймлохгүй, зөвхөн дэлгэцэнд гаргахдаа тоймлоно.
- `boundary`: нэгжийн гадна хил. Plan.dxf-ийн хилтэй 1 мм-ийн нарийвчлалтай таарахгүй бол төлөвлөлтийг ашиглахгүй.
- `walls[]`: тэнхлэг (`a`, `b`), `thickness`, `height`, `kind` (exterior / party / corridor / interior). Налуу хана дэмжигдэнэ.
- `openings[]`: `wall`-д холбогдоно. `offset` нь хананы эхнээс нүхний эхлэл хүртэлх зай (м); мөн `width`, `height`, `sill`. Хаалганы хувьд `swing.side` (хананы чиглэлийн зүүн/баруун) ба `swing.hinge` (start/end).
- `rooms[]`: өрөөний полигон (хананы дотор нүүрээр), `type`, `name`, `floor_finish`. Тэгш өнцөгт биш өрөө дэмжигдэнэ.
- `fixed_zones[]`: `kitchen` болон `plumbing` бүс. Гал тогоо, сантехникийн тавилга зөвхөн эдгээрт байрлана.
- `north_deg` (мэдэгдэхгүй бол `null`), `ceiling_height`, `source` (файл, хувилбар, sha256), `status.verification`.
- `area`: `declared` (үнэ үүгээр тооцогдоно) ба түүний тодорхойлолт; `boundary_definition`, `internal_definition`. Тооцоолсон талбайг зарласантай таарах гэж «засахгүй».

`status.verification` дөрвөн утгатай: `verified` (архитектор баталсан), `imported-unverified`, `demonstration`, `inferred`. Сүүлийн гурав нь UI дээр шар тэмдэглэгээтэй харагдана.

### Шалгалт (`validatePlan`)

Дараах тохиолдлыг алдаа гэж буцаана; bounding rectangle-ээр орлуулж «засахгүй»:
- Хаалттай биш эсвэл өөрөө огтлолцсон полигон, давхардсан орой.
- Масштаб хэт их эсвэл хэт бага (10–1000 м²).
- Хананы урт тэг, бодит бус зузаан эсвэл өндөр.
- Нүх хананаас гарсан, нүхнүүд давхацсан, sill болон өндрийн нийлбэр ханаас хэтэрсэн, хаалганы нээгдэх тал заагдаагүй.
- Өрөө хилээс гарсан, өрөөнүүд давхацсан, нэргүй өрөө.
- Бүс өрөөнөөсөө гарсан.

Талбайн зөрүү хүлцлээс (2%) хэтэрвэл анхааруулга өгнө.

## 2. CAD-аас импортлох (урсгал A)

`node tools/cad/plan-dxf.mjs import plan.dxf --id … --revision …` командыг ашиглана. Давхаргын дүрэм [tools/cad/README.mn.md](../tools/cad/README.mn.md)-д бий. Импортлогч нь дүрмийн дагуу тодорхой давхаргад зурсан объектыг л уншина. **Дурын CAD зургийг автоматаар ойлгохгүй. Растер болон PDF зургийг таних боломж хэрэгжээгүй.** Ийм зургийн хувьд дараах хоёр замын аль нэгийг ашиглана:
- CAD дээр зургийн доор ул мөр болгон тавиад, EP- давхаргуудаар гараар дахин зурна (manual tracing).
- `type-01.plan.json` загварын дагуу JSON-оор бичнэ.

Импортлогч дараах асуудлыг оношилж мэдээлнэ: нэгж ($INSUNITS эсвэл `EP-META units=`), муруй объект, давхардал, хаалттай биш полигон, шошгогүй өрөө, хананы тэнхлэг дээр биш нүх, давхцал, талбайн зөрүү. Үр дүнгийн `status` нь `imported-unverified` байна.

## 3. Бэлэн загварыг сайжруулах (урсгал B)

`/units/inspect.html` хуудас GLB файлыг шалгана:
- Хэмжээ, нэгжийн таамаг (м, см, мм, инч) болон дээд тэнхлэг (Y- эсвэл Z-up).
- UV байгаа эсэх, утгагүй нэртэй mesh, гурвалжны тоо, эх файлын SHA-256.
- Масштаб болон дээд тэнхлэгийг гараар сонгох удирдлагатай («Авто» нь зөвхөн таамаг).

Хана, шал, шил зэрэг үүргийг **зөвхөн гараар** материал тус бүрд онооно. Оноосон бүх үүрэг «гараар, баталгаажаагүй» төлөвтэй үлдэнэ. Сайжруулсан харагдац нь apartment viewer-тэй ижил лицензтэй PBR материал болон гэрэлтүүлгийг хэрэглэнэ. UV-гүй mesh-д texture-гүйгээр зөвхөн параметрийг нь хэрэглэнэ.

Эх GLB өөрчлөгдөхгүй. Масштаб, тэнхлэг, үүргийг `e-property.model-enhancement` JSON болгон тусад нь хадгалж, буцааж ачаална. Эх файлын SHA-256 таарахгүй бол анхааруулна. Загварт өрөөний мэдээлэл байхгүй бол өрөөг автоматаар таниагүй гэж шууд бичнэ.

Туршилт: `landing/units/assets/test/b0301-raw-cm-zup.glb` (`tools/assets/make-test-model.mjs`). Энэ нь жишээ төлөвлөлтөөс үүсгэсэн «боловсруулаагүй экспорт»: сантиметр, Z-up, `Mesh.001` болон `Material.001` нэртэй, өрөөний мэдээлэлгүй. Бодит орон сууцны загвар биш. `/units/inspect.html?sample=1` хаягаар нээнэ.

Хэрэгжээгүй: тохиргоог төсөлд хадгалж нэгжийн viewer-т автоматаар хэрэглэх, бэлэн загварын тавилгыг солих, GLB-ээс өрөөний полигон гаргах. Бодит гуравдагч талын орон сууцны GLB-ээр баталгаажуулаагүй (repo-д ийм загвар алга). Баталгаажуулахад орон сууцны бүрэн дотор загвар (хана, цонх, шалтай; дор хаяж нэг өрөө; м эсвэл см; UV-тэй) хэрэгтэй.

## 4. Тавилга

### Asset manifest

`landing/units/assets/manifest.json` (v2) нь asset тус бүрд дараахыг тодорхойлно:
- `id`, `category`, `dims` (м).
- `model`: файл, `rotY`, стиль бүрийн хувилбар; эсвэл `composite`.
- `anchor`, `clearance`, `variants`, `source`, `license`, `credit`, `status`.

Loader нь загварыг (glTF +Y дээш, урд тал +Z) `rotY`-ээр эргүүлж, footprint-ийн төвийг шалан дээр тавина. Унждаг гэрлийн хувьд дээд талыг таазанд тулгана. Хэмжээ 3%-иас илүү зөрвөл загварыг сунгахгүй, орлуулагч ашиглаж консолд мэдээлнэ. Загварууд кэшлэгдэнэ, файл алга бол орлуулагч руу шилжинэ.

| status | Тоо | Asset |
|---|---|---|
| `licensed` (бодит загвар) | 7 | sofa-3 (Wayfair GlamVelvetSofa, CC-BY 4.0), coffee-table, tv-unit (медиа шүүгээ), dining-set-4 (сандал + параметрт ширээ), nightstand, pendant-light, plant-floor (Poly Haven, CC0) |
| `parametric` | 10 | гал тогооны 4 модуль, 2 хувцасны шүүгээ, үүдний шүүгээ, тавиур, хөшиг, хивс. Өрөөнд тааруулж үүсдэг суурилуулсан тавилга, лицензтэй PBR материалтай |
| `substitute` | 7 | bed-double-160, bed-single-90, toilet, vanity-80, bathtub-170, shower-90, ceiling-light (таазны хавтгай гэрэл) |

Эх сурвалж, лиценз, хэмжээ, оновчлол бүгд `landing/units/assets/CREDITS.json`-д бичигдсэн. Татах, хөрвүүлэх скрипт нь `tools/assets/fetch-assets.mjs` (`cd tools/assets && npm install && node fetch-assets.mjs`). Түүний хийдэг оновчлол: dedup, prune, texture-ийг WebP ≤1024 px болгоно, эх загварт байсан гэрлийн эх үүсвэрийг хасна.

**CC-BY 4.0 (Wayfair) загварт нэр заах шаардлагатай.** Нэр нь нэгжийн хуудасны «Эх сурвалж» хэсэг, нүүр хуудасны footer, CREDITS.json-д бичигдсэн.

**Хараахан олдоогүй бодит загварууд** (CC0 эсвэл худалдан авсан, GLB, бодит хэмжээтэй, урд тал +Z):
- `bed-double-160`: 160×200 дэвсгэртэй, даавуу, дэртэй. Бодит хэмжээ ≈1.72×2.16×1.05 м.
- `toilet`: ≈0.40×0.66×0.80 м.
- `vanity-80`: ≈0.80×0.48×0.86 м.
- `bathtub-170`: ≈1.70×0.75×0.58 м.
- `shower-90`: ≈0.90×0.90×2.0 м.
- `ceiling-light`: хавтгай таазны гэрэл, ≈Ø0.45 м.

Эх сурвалжийн санал:
- Poly Haven болон Khronos sample-д эдгээр алга.
- Худалдан авах бол брэндийн BIM/GLB санг үзэх. Жишээ нь сантехникийн үйлдвэрлэгчийн BIM каталог (лицензийн нөхцөлийг шалгана).
- Эсвэл захиалгаар загварчлуулна.

Sketchfab зэрэг нэвтрэх шаардлагатай эх сурвалжийг ашиглаагүй.

| id | Эх | Хэмжээ |
|---|---|---|
| oak-floor | laminate_floor_02 | 1.7 м |
| plaster-warm | beige_wall_001 | 3.0 м |
| stone-tile | marble_01 | 1.5 м |
| wall-tile | long_white_tiles | 1.27 м |
| oak-veneer | oak_veneer_02 | 1.0 м |

### Хязгаарлалтад суурилсан байршуулалт (`lib/furnish.js`)

Тодорхой дүрмээр (AI-гүй) байршуулна. Дараахыг шалгана:
- Өрөөнд багтах эсэх, тогтмол бүс.
- Footprint мөргөлдөх (SAT).
- Ашиглах зай (clearance).
- Хаалганы нээгдэх болон орох бүс.
- Цонхны бүс (цонхны доод ирмэгээс өндөр тавилга хаахгүй).
- Явах зам: 5 см-ийн тор дээр flood fill хийж, хаалга бүр болон тавилга бүрийн хүрэх тал хүртэл `walkway` = 0.7 м өргөнтэй зам үлдсэн эсэх.

Дүрмийн утгууд `manifest.rules`-д бий. Эдгээр нь дизайны анхдагч утга бөгөөд норм, стандартад нийцсэн гэсэн баталгаа биш.

Байрлуулж чадаагүй тавилгыг оношилгоотой нь орхино. Жишээ төлөвлөлтөд бүх хөтөлбөр (32 зүйл) алдаагүй байрласан.

Гараар засах (`lib/interior-config.js`):
- Чирэх (5 см-ийн алхамтай), 90° эргүүлэх, устгах, ангиллын хүрээнд солих, материал солих.
- Буцаах (undo), дахих (redo), анхны байршил руу буцаах.
- Дүрэм зөрчсөн байршлыг татгалзаж, өмнөх байрлал руу буцаана.

Тохиргоо нь `ep-interior:<plan id>@<revision>` түлхүүрээр хөтчийн localStorage-д, архитектурын геометрээс тусдаа хадгалагдана. Нэг төрлийн бүх нэгжид хэрэглэгдэнэ. Төлөвлөлт шинэчлэгдвэл хуучин тохиргоог ашиглахгүй.

## 5. Viewer

- **Бүрхүүл:**
  - Хананы тэнхлэгийн уулзварт хананы төгсгөлийг хагас зузаанаар сунгана.
  - Цонхыг хүрээ, хуваагч, шил, дотор тавцантай хийнэ.
  - Хаалгыг хүрээ, нээгдэх зүг рүү 75° онгойсон хаалт, бариултай хийнэ.
  - Plinth (тавцангийн хаалт), усны өрөөнд 2.1 м хүртэл хавтан, тааз, плит.
  - Хананы хэсэгсэн дээд гадаргуу саармаг өнгөтэй (хуучин navy cap-ийг хассан).
- **Харагдац:**
  - Ерөнхий: камер руу харсан гадна ханыг 1.0 м-ээр хэсэглэнэ.
  - Дээрээс: бүх ханыг 1.15 м-ээр хэсэглэнэ.
  - Өрөө.
  - Дотроос: нүдний өндөр 1.5 м, FOV 62°, тавилга болон хананаас чөлөөтэй цэгээс цонх руу харна.
  - Хэсэглэлт нь зөвхөн харагдацын тохиргоо, геометр өөрөө бүтэн өндрөөрөө үлдэнэ.
- **Материал:**
  - Procedural (бодит метрийн масштабтай).
  - Шал 0.19 м өргөн банзтай, 4.8 м-т давтагдана.
  - Хавтан 0.6 м эсвэл 0.3 м.
  - Өнгөт map нь sRGB, roughness map нь шугаман.
- **Гэрэл:**
  - RoomEnvironment, нар зөөлөн сүүдэртэй, ACES tone mapping.
  - Оройн горимд гэрэл нь таазны гэрлийн байрлалаас тусна.
  - Нарны чиглэл нь жишээ, учир нь хойд зүг тодорхойгүй.
- **Гүйцэтгэл:**
  - 3D-г табаа нээхэд л ачаална.
  - Хэрэгтэй үед л render хийнэ.
  - Нуугдсан эсвэл дэлгэцнээс гарсан үед зогсоно.
  - Удаан бол pixel ratio-г 1, сүүдрийн map-ийг 1024 болгоно.
  - `dispose()` бүх нөөцийг цэвэрлэнэ.
  - Гар утсанд нэг хуруу хуудсыг гүйлгэж, хоёр хуруу загварыг эргүүлнэ.
  - WebGL байхгүй бол 2D зураг руу шилжинэ.

### 5.1 Харагдац ба гэрэлтүүлгийн шинэчлэл (2026-10-05)

- **Өдрийн гэрэл:** Цонх бүрт хэмжээгээрээ RectAreaLight байрлаж өрөө рүү гэрэл тусгана. Нар цонхнууд харсан тал руу 30° хазайсан байрлалтай.
  - Хойд зүг мэдэгдэхгүй тул нарны чиглэл нь жишээ. Бодит чиглэлээр батлахгүй.
  - Ерөнхий (dollhouse) болон дотор харагдацын гэрэл, exposure ялгаатай.
- **Оройн гэрэл:** Таазны гэрэл бүрт дулаан point light байрлана. Гэрлийн загварын материал гэрэлтэнэ. Нар болон цонхны гэрэл унтарна.
- **Contact shading:** GTAO (three 0.170 `GTAOPass`) «Өндөр» чанарт ажиллана. «Хөнгөн» горимд AO-гүй, pixel ratio 1, сүүдрийн map 1024 болно. Гар утсанд (coarse pointer) анхдагчаар «Хөнгөн». `?q=low|high`-ээр хүчээр тогтооно.
- **Камер:**
  - Дотроос харахад FOV 56°, нүдний өндөр 1.5 м.
  - Унтлагын өрөөнд ор руу, зочны өрөөнд буйдан руу харна.
  - Тавилгаас 0.3 м, ханаас 0.45 м, унжлагатай гэрлээс 1.7 м зайтай цэгт зогсоно.
- **Стиль:**
  - «Модерн» болон «Скандинав» нь хананы өнгө, шүүгээний нүүр (царсан шпон эсвэл цагаан лак), даавуу, хивс, ажлын тавцанг солино.
  - Буйдан нь бүтээгдэхүүний өөрийн хувилбар руу шилжинэ (KHR_materials_variants): Gray эсвэл Champagne.
  - Тавилгын байршил, хэрэглэгчийн засвар хэвээр үлдэнэ.

## 8. Хязгаар

- Бүтэцтэй төлөвлөлт нэг л байна (Туулын Эрэг, 01 төрөл). Энэ нь жишээ, архитекторын зураг биш. Бусад 278 нэгж таамагласан хуваалттай.
- Ор, сантехник, таазны хавтгай гэрэл одоо ч орлуулагч загвар. Тиймээс унтлагын болон угаалгын өрөө зочны өрөөнөөс бага бодит харагдана. Photorealistic гэж үзэхгүй.
- Python `dxf2glb.py`-г өөрчлөөгүй. Энэ орчинд Python байхгүй тул түүний тестийг ажиллуулаагүй.
- SwiftShader (CPU WebGL) дээр нэг кадр render хийхэд хэдэн минут шаардлагатай. Бодит GPU-тэй төхөөрөмж дээр FPS хэмжээгүй.
- Хүсэлт илгээх суваг, хуваалцах backend байхгүй. Зөвхөн холбоос хуулах нь ажилладаг.
- Inspect хуудасны mapping-ийг төсөлд хадгалах урсгал хараахан хийгдээгүй.
